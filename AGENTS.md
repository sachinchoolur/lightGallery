# lightGallery — guide for coding agents

This is the lightGallery monorepo: one lightbox/gallery library shipped as
four packages that share behavior. Read this before changing anything.

## Layout

| Path | What it is |
| --- | --- |
| `src/` | The vanilla `lightgallery` package (TypeScript) and its plugins under `src/plugins/<name>/` |
| `packages/headless/` | `@lightgallery/headless` — framework-free core: state machine, settings resolution, gesture/zoom/thumbnail math, URL drivers. No DOM. |
| `packages/react/`, `packages/vue/`, `packages/angular/` | Native framework packages. Each owns its DOM and reuses the headless logic. Plugins live in `plugins/<name>/` inside each package. |
| `packages/core/` | Vite build configs for the vanilla dist |
| `test/` | Vanilla test suites (Jest). Framework packages test under their own `src/` with Vitest. |
| `dist/` | Build output of the vanilla package. Regenerated by the build; committed only at release time. |
| `site-astro/` | The documentation website (Astro). Consumes the **built** packages, not source. |
| `skills/` | Agent skills. `skills/lightgallery/SKILL.md` teaches how to use the library in each stack. |

## Commands

```bash
npm test                                  # vanilla test suite
pnpm --filter @lightgallery/headless test # headless; same for react, vue, angular
npm run typecheck                         # vanilla types
npm run lint                              # vanilla lint (headless has its own config)
npm run build                             # vanilla dist
pnpm --filter @lightgallery/react build   # a package dist (headless, react, vue, angular)
npm run docs                              # TypeDoc JSON that the site's settings reference reads
pnpm --filter lg-site-astro build         # the website (run `npm run docs` and package builds first)
```

## Rules that matter

- **Behavior parity.** A feature or fix in one stack must be mirrored in the
  other three unless it is genuinely DOM-specific. Pure logic goes into
  `@lightgallery/headless` so every package shares it; runtimes only apply
  it to their own DOM.
- **Plugins are separate entries** in every package. Never make the core
  import a plugin.
- **Settings are documented at the source.** Every setting carries a JSDoc
  comment (description, default, `@version` for new ones, `See <a href>` to
  its docs page). The site's settings reference is generated from it.
- **Runtime warnings link to docs.** Any `console.warn`/`console.error` in
  library code ends with the URL of the page that explains the fix.
- **Commits** are conventional (`type(scope): summary`), header ≤ 72
  characters; commitlint enforces it.
- **Formatting** is Prettier (4-space indent, single quotes); a pre-commit
  hook formats `src/` and `test/`.
- Do not add dependencies to the library packages. They have none.

## Verifying changes

- Vanilla: `npm test` and `npm run typecheck`.
- Packages: `pnpm --filter <pkg> test` and `typecheck`.
- Website: `npm run docs`, rebuild any package you changed, then
  `pnpm --filter lg-site-astro build`. `pnpm --filter lg-site-astro check:examples`
  compiles every code example in the docs against the real packages —
  run it after editing documentation. The site's dev server does not
  hydrate the React islands; verify those on the built site
  (`pnpm --filter lg-site-astro preview`).
- Gesture feel (springs, fling, pinch) cannot be judged in a headless
  browser; those changes need a real touch device.
